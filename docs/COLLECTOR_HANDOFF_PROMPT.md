3. 정상 수집본 교체 시 계약 근거도 같은 트랜잭션 또는 일관된 성공 상태로 갱신한다.

## P0 작업

### 1. 구 분석 경로 운영 제거

- `src/yongin_collector/chat_analysis.py`, `csv_analysis.py`, `analysis.py`, 구 분석 API와
  정적 채팅 UI의 실제 import·라우팅·Compose·n8n 참조를 전수 확인한다.
- 현재 운영에서 사용하지 않는 질문 분석 코드와 의존성을 런타임에서 제거하거나 명확히

- 수집기 환경에서 `OPENAI_API_KEY`를 읽거나 요구하지 않게 한다.

### 2. 분석용 수집 버전 계약

기존 원본·현재 레코드를 수정하지 말고, 마이그레이션으로 읽기 전용 계약 뷰 또는 테이블을
추가한다. 최소 필드는 다음과 같다.

- `dataset_id`
- 마지막 정상 원본 SHA-256
- 마지막 정상 수집 실행 ID
- `last_success_at`, `collected_at`, `reference_date`
- 현재 행 수와 컬럼 수
- 정렬된 컬럼명으로 만든 스키마 서명
- 원본 파일명 또는 ZIP 내부 멤버 식별자
- 품질 검증 상태와 검증 시각

분석 계정 `yongin_analysis_reader`에는 SELECT만 부여한다. 쓰기 권한은 부여하지 않는다.
계약은 성공한 현재 스냅샷과 정확히 연결돼야 하며, 수집 실패·부분 실패 때 앞선 정상 계약을
덮어쓰지 않는다.

### 3. 수집 시점의 구조 근거 보존

- CSV 검증 중 이미 얻는 헤더, 인코딩, 구분자, 행·컬럼 수, 기준일, 고유키, 필수값 검사
  결과를 성공 실행 메타데이터에 보존한다.
- 승인된 데이터셋에서 수행한 숫자 형식·날짜 형식·행별 합계 일치 검사는 검증 규칙 이름과
  통과 여부만 보존한다. 구별 합계·평균·순위 같은 분석 통계는 만들지 않는다.
- ZIP 자료는 원본 ZIP SHA와 내부 CSV SHA·멤버 이름의 연결을 유지한다.

### 4. 분석 프로젝트와 계약 확인

  `yongin_analysis_login` 또는 동등한 읽기 전용 계정으로 조회한다.
- 적재된 데이터셋 ID를 코드에 고정하지 않는다.
- 인구 자료 `portal_csv_15135861`에서 기준일, 39행, 컬럼 서명이 계약과 현재 레코드에
